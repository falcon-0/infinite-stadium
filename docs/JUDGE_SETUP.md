# Run Infinite Stadium from the source build

The source build includes synthetic data generators, the fan interface and legacy producer source, server code and tests. It excludes Azure credentials, the developer's environment files, installed dependencies, model weights and runtime budgets. The included `.env.example` contains placeholders only.

## Run the recorded experience

Use Node.js 20 or newer; development validation currently uses Node.js 24. Extract the ZIP, open a terminal in its `infinite-stadium` folder, and run:

```sh
node server.js
```

Open `http://127.0.0.1:4173/`. No package installation, Python environment, account or credentials are needed for the synthetic replay, recorded explanations, personalization, buildup replay and recorded recap. Use a recent Chrome, Edge, Firefox or Safari browser. Stop the server with Ctrl+C.

Watch opens with twenty synthetic matches across five passage families. Select a fixture, press **Play match**, and watch at the fixed 2× demo playback speed. The banner follows ordinary actions; score and compact statistics stay alongside the replay. **Ask about the match** accepts freeform questions when Azure is available, captures the current match timestamp and lets playback continue. Choose a language in Viewing options and press Apply view. It changes match statistics, insights, recaps and future match answers; existing conversation turns keep their original language. Menus and curated general-rule references currently remain in English. A real Spanish Azure answer and all four applied statistic languages were checked; broad multilingual quality and native-language review remain pending. Watch reports AI unavailability without substituting scripted search. At the end, choose **View recap**. Studio is no longer part of the site; old Studio links open Watch. In Northbridge-Harbour, the shot at 01:56 remains pending until confirmation at 01:58.

**AI explanation and AI recap require a separately configured provider.** An unconfigured source build keeps recorded insights usable and does not claim that they were generated by a model. Do not put API credentials into client-side files or the distributed ZIP. Provider setup and limitations are in the main README. A local model is optional and is not included or downloaded by these steps.

## Verify the actual ZIP in a clean directory

Python 3.9 or newer and Node.js are required for this optional verifier. It uses only Python's standard library, installs nothing, makes no model calls, and accesses only its own loopback server. From the source folder:

```sh
python package_judge.py
python verify_judge_package.py
```

To check an existing downloaded archive, pass its path instead:

```sh
python verify_judge_package.py path/to/infinite-stadium-test-build.zip
```

The verifier checks source hashes and the file allowlist, extracts into a fresh temporary directory, starts the packaged server on a free loopback port with a sanitized environment, requests the browser module graph and CSS, checks pending/confirmed scoring and SSE completion, and confirms AI is unconfigured. It stops only the process it created and removes only its temporary directory. A JSON result prints to the terminal. Use `--report path/to/report.json` to save it in an existing directory.

This is an isolated extraction on the computer running the check. It does not substitute for testing on a second computer, browser visual review, accessibility review, real fan feedback or cloud-model validation. The verifier statically checks Docker stylesheet inclusion; it does not build or run Docker.

The ZIP and its separate SHA-256 file are created under `artifacts/judge/`. Every source file also has a hash in `BUILD_MANIFEST.json`. Fixed ZIP metadata makes unchanged source reproduce the same archive with the same Python/zlib implementation. A manifest detects accidental modification; it is not a cryptographic publisher signature.

Run packaging regression checks with:

```sh
python -m unittest package_judge_test.py
```

Run the application checks with `npm test`. Model calls are not part of the default tests.

## Optional Docker deployment

The Dockerfile uses Node.js 24, includes the frontend styles, and creates `/app/.runtime` owned by the non-root `node` user. Docker must already be installed; building can download its base image. The container binds `0.0.0.0:8080`. Any public binding requires both a private `APP_ACCESS_TOKEN` of at least 32 characters and an HTTPS `PUBLIC_ORIGIN`, including a container mapped only to the local computer. These checks do not configure TLS: a public deployment needs HTTPS from its hosting platform or reverse proxy.

The image build succeeded during development. A later `--load` attempt failed when the Docker daemon returned EOF and disappeared. **No successful Linux container runtime check is recorded.** The source cleanroom check runs a separate Node process on the development computer and is distinct from Docker validation.

### Local Docker check without cloud AI

These PowerShell commands build and run only the recorded experience. They do not pass Azure credentials or an environment file into the container. The generated access token is disposable and used only for this local container:

```powershell
docker build -t infinite-stadium:local .
$stadiumLocalToken = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
docker run --rm --name infinite-stadium-local-check -p 127.0.0.1:8080:8080 -e "APP_ACCESS_TOKEN=$stadiumLocalToken" -e PUBLIC_ORIGIN=https://local-check.invalid -e MAX_DAILY_MODEL_CALLS=1 infinite-stadium:local
```

Leave that terminal running. In a second PowerShell terminal:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
Invoke-RestMethod http://127.0.0.1:8080/api/ai/status
```

Health should report `healthy: true`; AI should report `configured: false`. Open `http://127.0.0.1:8080/` and check the recorded match. `https://local-check.invalid` is only a syntactically valid origin placeholder for this loopback-only check; do not browse to it or use it for a real public deployment. The local HTTP URL does not demonstrate working production HTTPS. Stop the foreground container with Ctrl+C; `--rm` removes that test container. The disposable variable can then be cleared with `Remove-Variable stadiumLocalToken`.

### Public Azure configuration and persistent storage

Supply configuration at runtime through the host's private environment/secret settings. Do not bake it into the image or source archive.

- Set `PUBLIC_ORIGIN` to the real HTTPS origin, such as `https://your-deployment.example`, without a path, query or credentials. Set a private `APP_ACCESS_TOKEN` of at least 32 characters.
- With Azure configured on a public binding, explicitly set `MODEL_BUDGET_FILE=.runtime/azure-model-budget.json`. Startup rejects a missing budget path. Set `MAX_DAILY_MODEL_CALLS` to the already approved request allowance; do not raise it as part of deployment.
- Mount persistent storage at `/app/.runtime`. The `node` user must be able to create and update files there. A writable container layer alone does not preserve the ledger when the container is replaced. A bind mount can override the ownership supplied by the image, so check the mounted permissions.
- Retain the existing authorized ledger when migrating or restarting. Do not delete or replace it to reset reservations. The file is a same-filesystem request counter, not a dollar cap or a distributed quota across replicas. A multi-replica deployment needs a shared quota design before it can claim one global allowance.

For Docker, a named volume can be created explicitly with `docker volume create infinite-stadium-runtime`, then attached with `--mount type=volume,source=infinite-stadium-runtime,target=/app/.runtime`. This volume should remain attached to replacement containers. Permission checking can be done without launching the application or making any model call:

```powershell
docker run --rm --mount type=volume,source=infinite-stadium-runtime,target=/app/.runtime --entrypoint node infinite-stadium:local -e "const fs=require('node:fs'); fs.accessSync('/app/.runtime',fs.constants.W_OK); console.log('Runtime directory is writable');"
```

Creating a new empty volume is not a migration of an existing budget ledger. Preserve that ledger through the deployment's storage migration process. This guide prepares configuration; it does not establish a hosted judge URL, successful container execution, public deployment or judging-period availability.

## Single-command local release check

Run `npm run verify:release` with Node.js 24 and Python available. It runs the Node suite, fixture checks including the twenty-match catalogue, stream/query/display consistency, offline moment and recap evaluations, packaging tests, archive creation and clean-directory verification. It supplies no model credentials and makes no model calls. Logs and a machine-readable result are saved in `artifacts/release/`.

A passing result establishes only those local gates. It does not mean the website is publicly deployed, Docker runs, the video is recorded or fans have tested it. Current delivery status is maintained in SUBMISSION.md; deployment steps are in DEPLOYMENT.md.
